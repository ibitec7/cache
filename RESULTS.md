The hit-count regression is the obvious alternative and it **loses to the floor** on every trace: frequency is a proxy for popularity, not for distance, and the conversion is where it dies. The oracle row is a harness check, not a result; its error is floating-point noise because it reads the curve it is being scored against.

Hit-count and the oracle were not run per window, so they do not appear in Sections 1 and 2. Neither omission flatters the model: one is worse than the floor the model already beats, the other is unattainable.

**The finding that matters more than the configuration.** Stop each study at trial 12 and the winner is not a search result: 3 of 4 traces pick the *identical* configuration (`num_leaves=15, learning_rate=0.0969535, min_data_in_leaf=207, feature_fraction=0.900711, bagging_fraction=0.624538, lambda_l2=0.0044191`), because seeded TPE spends its first 10 trials on random draws. Twelve trials is two informed trials wearing a sampler's name, and what it ranks is capacity order across traces, not a hyper-parameter effect. Extending the studies past trial 20 makes them diverge per trace (the rows above) and lowers the validation objective by 1.03x to 1.14x. Hence the rule: **a study is reported only if it ran past trial 20.**

Search was frozen with `--trials 0` for the retrain, LOCO and baseline experiments, on purpose: each varies one axis, and re-tuning inside them would confound that axis with the configuration.

## 6. Where the claim stops

| limit | consequence |
|---|---|
| LRU replacement only | the curve is not the miss ratio of TinyLFU, S3-FIFO or any admission policy, and no error bound is measured for that substitution |
| capacity counted in objects | a byte-weighted curve is what a provisioning decision wants; the code can do it, these numbers are objects |
| one corpus, four traces | evidence about one service's key-value cache, not about storage, CDN or database workloads |
| censoring at the trace boundary | a streaming deployment censors earlier, at the point of prediction |
| 32 buckets, cap at the train p99.9 | the curve is exact only below that cap |
| frozen model | no online adaptation; retraining is a schedule, not a method |
| level offset uncalibrated | the model under-predicts, i.e. errs toward under-provisioning, which is the expensive direction |
